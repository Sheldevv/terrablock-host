# TerraBlock Host

A provider-independent Node.js launcher and TCP gateway for the existing TerraBlock LÖVE server.

## Quick start (Linux x86_64)

1. Install Node.js 20.6 or newer.
2. Put the archive generated by `./server/pack.sh` at `game/TerraBlock-server.love`.
3. Configure the host:

   ```sh
   cp .env.example .env
   ```

4. Start it:

   ```sh
   npm start
   ```

The launcher checks for LÖVE 11.5. If the exact version is already installed,
it uses that. Otherwise, it downloads the official LÖVE 11.5 x86_64 AppImage,
extracts it into `.runtime/`, and runs the extracted binary. This is project-local:
it does not install system packages, require sudo, or modify the OS.

You can also install the runtime ahead of time with:

```sh
npm run setup
```

The official LÖVE download page provides the Linux AppImage, and the LÖVE
distribution documentation describes extracting the AppImage and using the
relocatable binary. See:
- https://www.love2d.org/?page=download
- https://love2d.org/wiki/Game_Distribution

## Requirements and limitations

- Node.js 20.6+
- Linux x86_64 for automatic AppImage setup
- `curl` or `wget` for first-time runtime download
- The LÖVE server archive at `game/TerraBlock-server.love`
- LuaSocket 3.x compiled for the LuaJIT/Lua 5.1 runtime used by LÖVE

**Important:** The current official LÖVE AppImage does not guarantee that
TerraBlock's native LuaSocket module is included. The game server still needs
`require("socket")` to work. If the AppImage runtime cannot load LuaSocket,
the launcher will show the server's error. LuaSocket provisioning is a separate
native-module packaging task; a module built for system Lua is not necessarily
compatible with LÖVE's LuaJIT runtime.

The automatic AppImage path is currently x86_64 only. Other Linux architectures
must install LÖVE 11.5 through their distribution or provide a matching runtime.

## Configuration

Copy `.env.example` to `.env`:

| Variable | Default | Meaning |
|---|---:|---|
| `HOST` | `0.0.0.0` | Gateway bind address |
| `PUBLIC_PORT` | `22120` | Client-facing TCP port |
| `GAME_HOST` | `127.0.0.1` | Internal LÖVE server address |
| `GAME_PORT` | `22121` | Internal LÖVE server port |
| `GAME_SEED` | `424242` | World seed |
| `GAME_ARCHIVE` | `./game/TerraBlock-server.love` | LÖVE server archive |
| `LOVE_BIN` | `love` | Use system LÖVE or set a custom executable path |
| `ALLOW_PUBLIC_UNSAFE` | `false` | Explicitly bypasses the public-exposure safety guard |
| `ALLOW_IPS` | empty | Optional comma-separated client IP allowlist |

## Security warning

The supplied TerraBlock server README says the protocol is unauthenticated and
unencrypted and explicitly warns against exposing it to the public internet.
The starter therefore refuses to bind a public address unless explicitly
overridden. Do not override this guard for an internet-facing server until the
client/server protocol has authentication, encryption, message validation,
size limits and rate limits. An IP allowlist is not a substitute.

## What this starter does

- Starts the existing `TerraBlock-server.love` process.
- Passes the configured world seed and internal TCP port to LÖVE.
- Exposes a Node.js TCP gateway and forwards client traffic to the Lua server.
- Supports optional source-IP allowlisting.
- Automatically provisions the LÖVE 11.5 runtime on Linux x86_64 when needed.

It is a transparent TCP proxy, not a protocol rewrite. It does not add player
inventory synchronization, crafting, mob drops, world persistence,
authentication, or encryption.

## Hosting

A persistent Linux VM or Docker host is the intended target. The current
implementation is a raw TCP listener and cannot be deployed unchanged as a
Vercel Function. A Vercel adapter would require a WebSocket client transport
and a persistent authoritative game simulation architecture.
